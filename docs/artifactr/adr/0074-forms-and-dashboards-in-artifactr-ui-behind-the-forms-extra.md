# ADR-0074: Forms and dashboards in `artifactr.ui`, behind the `forms` extra

**Status:** Accepted
**Date:** 2026-10-17
**Deciders:** Alex Nodeland

## Context

[lattice RFC-0005](../../rfcs/0005-forms-dashboards-and-mini-apps.md) puts forms, dashboards and, later, mini apps in the chat: a JSON Schema subset and its validator, four artifact types, an agent toolset, and the checks that refuse a bad submission. It proposed a distribution of its own (O1). The owner decided instead that lattice's integrations are not separate distributions: each is a module of the library it extends, installed by an extra of it. Forms extend artifactr alone, so they are a module of artifactr's.

## Decision

- **The module is `artifactr.ui`,** a layer of artifactr's: `schema` (the subset and its hints), `types` (the `form`, `submission`, `dashboard` and `app` kinds, and `ask_form`'s request), `ids` (a submission's derived id), `integrations` (which are on in a workspace, [ADR-0080](0080-integrations-on-or-off-per-workspace.md)), `checks` ([ADR-0075](0075-forms-refused-at-the-boundary-through-the-checks.md)), `agent` (the toolset, [ADR-0078](0078-the-agents-toolset-for-forms-and-no-apps-yet.md)), `wire` (the wire schema), and a private `_common`.
- **It is a plugin.** Nothing else in artifactr imports it, so an application that doesn't import it registers none of its types and runs none of its checks. It depends inward only, on names in `__all__` of `artifactr.core`, `artifactr.agent` and `artifactr.workspace`. `tests/ui/test_layering.py` holds both, and the layering test lists it as a layer.
- **It is installed by the `forms` extra,** `artifactr-ai[forms]`, which is empty today: it needs only Pydantic, which artifactr requires already, and Pydantic's core, which artifactr now names since `artifactr.ui` raises its custom errors. The extra is the stable name an application installs it by, which any dependency the forms ever need joins, so an application never changes how it asks for them.
- **relayr bridges it,** in `relayr.ui` behind relayr's own `forms` extra ([relayr ADR-0033](../../relayr/adr/0033-one-event-for-both-ways-of-asking.md)): artifactr can't depend on relayr.
- **Its wire schema is artifactr's,** `schemas/artifactr_ui.v1.json`, regenerated by `moon run artifactr:schema` beside the protocol's and drift-tested as they are; portalr generates its types from it. Its fixed fields, an implied `type` among them, are required, as [ADR-0063](0063-the-openapi-documents-describe-refusals.md)'s test holds every committed schema to.
- **Its tests are artifactr's,** in `tests/ui/`, on artifactr's storages and `ARTIFACTR_TEST_POSTGRES_URL`, with the vectors portalr's TypeScript tests read in `tests/ui/vectors/`.

## Options considered

| Option | For | Against |
|---|---|---|
| **A layer of artifactr, behind an extra (chosen)** | One release; no distribution, PyPI project or environment of its own; artifactr's tests and storages | artifactr's reference grows; a layer nothing else imports, held by a test |
| A distribution of its own (RFC-0005's O1) | Its own release cadence | A package, release and floors to stage for each integration |
| Always on, with no extra | Nothing to install | No name to add a dependency to later |

## Consequences

- Easier: `uv add "artifactr-ai[forms]"` and `from artifactr.ui import UI_TYPES, ui_checks`; forms release with artifactr.
- Harder: a change to forms releases artifactr.
