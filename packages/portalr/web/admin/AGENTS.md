# AGENTS.md: admin

[web/AGENTS.md](../AGENTS.md) applies; this adds what is specific to the admin UI.

- Routes are TanStack Router files; `src/routeTree.gen.ts` is generated by the Vite build. Don't edit it.
- Unit tests are Vitest (`vitest.config.ts`). Scenarios are Gherkin in `bdd/features/`, one per area, with steps in `bdd/steps/`, run by playwright-bdd (`playwright.config.ts`).
- `moon run admin:bdd` builds the UIs, starts portalr's test application (`../../tests/app/`) with Supabase Auth, and runs the features ([ADR-0013](../../../../docs/portalr/adr/0013-the-apps-scenarios-against-the-test-application.md)). It needs Docker; it installs Chromium via `ui:chromium`.
- A new user-facing behaviour gets a scenario, not only a unit test.
- Every setting lattice-core declares needs a label in admin's `LABELS` (`tests/test_portalr_settings_labels.py`).
- Shared components belong in `ui`, API calls in `client`; keep this package to routes and screens.
