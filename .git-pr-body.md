Colour-blind mode, as a setting a person chooses (ADR-0036's hook, which nothing set until now).

- **A switch in the account menu,** under **Colour**, in both UIs (one shared `Account`): a checkbox menu item (`menuitemcheckbox`, `aria-checked`), reached and toggled by the keyboard like the menu's other items.
- **Per browser, kept like the scheme:** `portalr-colour-blind` in `localStorage` (`"on"` or absent), read and written inside `try`, so without storage it lasts as long as the page. Not stored on the server.
- **Applied before the first paint:** `scheme.js`, the script the UIs already load for the scheme, now also sets `data-cvd` on the root, so the mode never flashes on after the page.
- **The palette is wired to the hook and holds:** `[data-cvd]` swaps the chart inks and turns every hatch, dash and marker shape on; the existing tests hold it to 3:1 on paper and surface and to CIEDE2000 of 20 or more under protanopia, deuteranopia and tritanopia. Status colours stay identical in the mode (a new test), since they hold the floors on their own.
- **Forced colours:** under `forced-colors: active` every pattern is on whether the mode was chosen or not (the system's colours replace the hues); a test emulates it.
- **Docs:** both guides drop the "not built" bullet and say where the setting lives and that it is per browser; `docs/portalr/index.md` no longer lists it as unbuilt; ADR-0036 has a dated amendment; `tests/test_portalr_guides.py`'s "nothing sets data-cvd" test is now a test that the setting is where the guides say.
- **Tests:** the hook (default off, on sets the attribute and storage, off clears both, kept choice, no storage), `scheme.js` (sets the mode before paint, nothing without storage), the menu item (role, state on and off, a key toggles it), forced colours, status colours unchanged in the mode; screenshots of the status/alert/card sheet with the mode on (light and dark) and of the open account menu; a BDD scenario in app and in admin (turn on, reload, still on, turn off).

Verified serially with `--force`: `ui`, `admin`, `app` checks, `lattice:knip`, `portalr:check`, `admin:bdd` and `app:bdd`; the guides test and `lattice:docs`. Baselines come from CI's artifact.
