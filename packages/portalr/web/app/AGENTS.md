# AGENTS.md: app

[web/AGENTS.md](../AGENTS.md) applies; this adds what is specific to the people's UI.

- Routes are TanStack Router files; `src/routeTree.gen.ts` is generated by the Vite build. Don't edit it.
- Unit tests are Vitest (`vitest.config.ts`). Scenarios are Gherkin in `bdd/features/`, one per area, with steps in `bdd/steps/`, run by playwright-bdd (`playwright.config.ts`).
- `moon run app:bdd` builds the UIs, starts portalr's test application (`../../tests/app/`) with Supabase Auth, and runs the features ([ADR-0013](../../../../docs/portalr/adr/0013-the-apps-scenarios-against-the-test-application.md)). It needs Docker; it installs Chromium via `ui:chromium`.
- A new user-facing behaviour gets a scenario, not only a unit test.
- `bdd/generated/` and `scripts/generated` run the scenarios against a generated application (`PORTALR_FEATURES`); keep those features in step with `bdd/features/`.
- Its tests read the analytics allow-lists in `../../src/portalr/analytics/`; the recorder's `replay_allowlist.json` is shared with the relay ([ADR-0077](../../../../docs/portalr/adr/0077-session-replay-its-own-yes-masked-in-the-browser-and-checked-at-the-relay.md)).
- Shared components belong in `ui`, API calls in `client`; keep this package to routes and screens.
